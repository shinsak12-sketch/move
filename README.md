# 거주지 · 발령 희망 조사 (주소 취합 사이트)

직원이 휴대폰으로 거주지 주소와 발령 희망을 입력함. 서버가 전국 센터까지의 자동차 경로 거리를 계산함(네이버 최적 경로). 주소 검색창은 카카오(다음) 우편번호 서비스(키 없음), 좌표 변환과 거리는 네이버 클라우드 Maps 키 하나로 처리함. 결과는 엑셀로 받아 회사 보안망으로 옮김. 설계는 `DESIGN.md` 참고.

- 직원 화면: `/`
- 관리자 화면: `/admin.html`

## 구조
| 경로 | 내용 |
|---|---|
| `index.html`, `assets/app.*` | 직원 화면 (빌드 없음, 일반 HTML/JS) |
| `admin.html`, `assets/admin.*` | 관리자 화면 (키 만들기 · 복호화 · 엑셀 생성은 브라우저 안에서만) |
| `assets/xlsx.full.min.js` | 엑셀 읽기/쓰기 (SheetJS 0.18.5, Apache-2.0) |
| `api/*.js` | Vercel 함수 (직원) — login · consent · password · public · me · calc · submit |
| `api/admin/*.js` | Vercel 함수 (관리자) — login · status · roster · orgs · account · export · settings · wipe |
| `lib/` | DB(Neon) · 보안(HMAC · 공개키 암호화 · 토큰) · 네이버 호출(좌표 · 거리) · 설정 |

DB 표는 첫 요청 때 자동으로 만들어짐(`lib/db.js`).

## 개인정보 처리
| 항목 | 서버(Neon)에 남는 것 |
|---|---|
| 이름 · 생년월일 | HMAC 해시(로그인 확인용) + **공개키 암호문**(관리자만 해독) |
| 본부 · 부서 · 센터 (명단) | 그대로 저장 (진행 현황 집계용) |
| 비밀번호 | bcrypt 해시 |
| 현 주소 · 이전 주소(도로명까지, **동 · 호수 등 상세주소는 받지 않음**) · 이사 예정지(동까지) · 사유 서술 | **공개키 암호문**만. 거리 산출 때 서버 메모리에서만 잠깐 쓰고 버림. 좌표는 저장 안 함 |
| 희망 지망 (1~3지망 부서 + 부서별 센터 최대 3곳, 1지망 '발령 희망하지 않음' 가능) | 조직코드로 저장 |
| 거리 · 소요시간 · 체크값 · 구분값 · 희망 센터코드 | 그대로 저장 (개인 식별 정보 아님) |

- 서버에는 **공개키만** 있음. 개인키는 담당자 PC에 파일(키 비밀번호로 잠금)로만 있음 → 서버나 DB가 새도 원문을 못 봄.
- 직원이 입력 중인 내용은 그 휴대폰 브라우저의 sessionStorage에만 있음(탭을 닫으면 사라짐).
- 요청 본문은 서버 로그에 남기지 않음.

## 처음 설정 순서
1. **Neon**: 이 조사 전용 프로젝트(또는 DB)를 만들고 연결 문자열을 복사함
2. **Vercel**: 새 프로젝트 → `move` 저장소 → Root Directory는 그대로(루트), Framework = Other
3. **환경변수** (Vercel › Settings › Environment Variables)

   | 이름 | 값 |
   |---|---|
   | `DATABASE_URL` | Neon 연결 문자열 |
   | `HMAC_SECRET` | 긴 임의 문자열 (예: `openssl rand -hex 32`). **조사 중 바꾸면 로그인이 안 됨** |
   | `TOKEN_SECRET` | 긴 임의 문자열 (선택. 없으면 HMAC_SECRET에서 만듦) |
   | `ADMIN_ID` · `ADMIN_PASSWORD` | 관리자 계정 1개 (비밀번호는 16자 이상 무작위 권장) |
   | `ADMIN_TOTP_SECRET` | 관리자 Google OTP 비밀값. 관리자 화면 [키 관리]에서 등록하면 나오는 값. 넣고 재배포하면 OTP 필수 |
   | `DIST_SECRET` | 거리값 암호화 키 (선택. 없으면 HMAC_SECRET에서 만듦). **조사 중 바꾸면 저장된 거리를 못 읽음** |
   | `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET` | 네이버 클라우드 Maps 인증키 (**Geocoding + Directions 5** 둘 다 이용 신청). HR노트 사택 신청과 같은 키 써도 됨 |
   | `NAVER_GEOCODE_URL` · `NAVER_DIRECTIONS_URL` | (선택) 기본값 `https://maps.apigw.ntruss.com/map-geocode/v2/geocode` · `…/map-direction/v1/driving` |
   | `ENC_PUBLIC_KEY` (또는 `PUBLIC_KEY`) | 4번에서 만든 공개키. `PUBLIC_KEY` 이름은 Vercel 이 Sensitive 로 못 저장하니 `ENC_PUBLIC_KEY` 추천 |

4. **키 만들기**: 배포 후 `/admin.html` 로그인 › **키 관리** › 키 비밀번호 입력 › [키 만들기]
   - 개인키 파일이 내려받아짐 → **담당자만 보관**. 잃어버리면 자료를 못 엶
   - 화면의 공개키를 `ENC_PUBLIC_KEY`에 넣고 **다시 배포**함
5. **조직 주소 업로드**: 엑셀 머리글 `조직코드 · 구분(부서/센터) · 권역(수도권/지방) · 부서 · 센터명 · 주소` (관리자 › 조직 주소 › [양식 내려받기]). 주소는 원본 그대로 넣어도 됨 — 층 · 호수 · 건물명을 떼고 같은 건물은 한 번만 계산함. 좌표 실패가 뜨면 주소를 고쳐 다시 올림
   - 직원 화면 거리 결과는 **부서 카드**(권역 필터)와 **센터 카드**(권역 · 부서 필터)로 나뉘어 나옴
   - 희망 지망: 1 · 2 · 3지망 **부서**를 고르고, 부서마다 그 부서 **센터를 최대 3곳** 고름. 1지망에 **발령 희망하지 않음**을 고르면 2 · 3지망은 "발령이 난다면" 희망하는 곳이 되고, 희망 사유 단계는 건너뜀
6. **명단 업로드**: 엑셀 머리글 `본부 · 부서 · 센터 · 이름 · 생년월일` (관리자 › 명단 › [양식 내려받기]). 생년월일은 6자리, 8자리, 날짜 모두 됨
7. 직원 링크(`https://<도메인>/`)를 사내 메신저로 안내함

## 운영
- **진행 현황**: [개인키 불러오기]를 누르면 이 창에서만 이름이 보임. 미제출 명단 복사, 비번 초기화, 잠금 해제, 재작성 허용, 산출 횟수 초기화
- **설정**: 접수 열기/닫기, 사택 기준 km, 사유 구분값, 동의서 문구(고치면 버전이 올라가고 직원은 다음 접속 때 다시 동의함)
- **내려받기**: 정보 · 조직 · 응답 · 거리 · 소요시간 · 사택대상 · 미제출 시트로 된 엑셀(브라우저에서 복호화)
- **전체 파기**: 조사가 끝나고 엑셀을 보안망으로 옮긴 뒤, `파기`를 입력하고 실행함 → 명단 · 계정 · 동의 · 응답 · 거리 · 기록이 전부 삭제됨

## 알아둘 점
- 네이버 Directions에는 "순수 최단거리" 옵션이 없음. **최적 경로(traoptimal)** 기준으로 계산함
- 직원 1명이 산출하면 (실제 주소가 다른 조직 수)만큼 네이버를 호출함
- **거리 산출은 1인당 2번까지**(처음 1번 + 재산출 1번). 3번째는 막히고 담당자 연락 안내가 나옴. 필요하면 관리자 › 진행 현황에서 [산출 횟수 초기화]
- 네이버 Directions 5 무료 한도는 대표 계정당 월 6만 건 → 860명 × 약 60곳이면 한도에 가까우니, 조사는 한 달 안에 끝내는 게 좋음
- 서버에 주소 원문이 없어서 관리자가 거리를 대신 다시 계산할 수는 없음 → [재작성 허용] 후 직원이 다시 입력해야 함
- 제출 후에는 직원이 수정할 수 없음. 안내 연락처: 손사지원파트 신이삭 수석 (`lib/settings.js`의 `CONTACT`)
